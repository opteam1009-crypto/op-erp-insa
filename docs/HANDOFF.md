## 로컬에서 다시 시작하려면

```bash
git clone https://github.com/opteam1009-crypto/op-erp-insa.git
cd op-erp-insa
npm install
cp .env.local.example .env.local   # 값은 아래 참고
npm run dev
```

`.env.local`에 넣을 값 — **이 저장소에 없다. 따로 옮겨와야 한다:**

| 변수 | 어디서 |
|---|---|
| `DATABASE_URL` | Neon 대시보드 → Connection string (풀링된 것) |
| `APP_PASSWORD` | 로그인 비밀번호. 현재 `1234` |
| `SESSION_SECRET` | 기존 값을 그대로 옮기거나 `openssl rand -hex 32`로 새로 발급. **바꾸면 기존 세션이 전부 만료된다** |
| `BLOB_READ_WRITE_TOKEN` | Vercel → Storage → Blob 연결 시 발급 |
| `SLACK_WEBHOOK_URL` | 알림 채널 webhook. 없으면 크론은 돌지만 아무 데도 안 보낸다 |
| `CRON_SECRET` | `openssl rand -hex 32` |

DB 스키마는 **이미 적용되어 있다.** 새 Neon 프로젝트를 만드는 게 아니라면
`db/schema.sql`을 다시 돌릴 필요 없다.

## 남은 일

### 1. Vercel 배포 (막혀 있는 유일한 것)

1. `opteam1009-crypto/op-erp-insa`로 새 프로젝트 생성
2. **Storage → Neon 연결** — `DATABASE_URL` 자동 주입
3. **Storage → Blob 연결** — `BLOB_READ_WRITE_TOKEN` 자동 주입
4. `APP_PASSWORD`, `SESSION_SECRET` 직접 추가 (크론 쓸 거면 `CRON_SECRET`, `SLACK_WEBHOOK_URL`도)

배포 후 `1234`로 로그인해서 사원 9명이 보이면 끝.

### 2. 미구현 기능

원래 요구사항 중 안 만든 것:

- **입퇴사자 알림.** `resignation_date` 컬럼은 있고 데이터도 들어 있는데 읽는
  곳이 없다. 입사 예정/퇴사 예정 리마인더가 없다.
- **일정 화면.** 알림은 Slack으로만 간다. "이번 달 정규직 전환·생일·입퇴사"를
  한눈에 보는 화면이 앱에 없다.
- **연봉협상일 자동 계산.** 수동 입력이다. 원본 인사대장의 `연봉협상평가일`이
  "10월", "11월"처럼 월만 적혀 있는 걸 보면 매년 반복되는 규칙 같은데, 지금
  스키마는 단일 날짜 하나만 담는다. 규칙을 정해야 만들 수 있다.
- **파일 다운로드.** 업로드한 증빙·급여대장을 UI에서 내려받을 경로가 없다.
  `file_path`를 저장만 하고 읽는 곳이 없다. Blob은 private이므로 세션 검사를
  붙인 라우트 핸들러로 스트리밍해야 한다.

## 조심할 것

### 인증 모델

**공용 비밀번호 하나다. 계정도 역할도 없다.** 비밀번호를 아는 사람은 급여대장과
손익 정산까지 전부 본다. 사용자가 한 명이라는 전제 위에 서 있고, **두 번째
사용자가 생기면 이 전제가 깨진다.**

Supabase 시절의 RLS가 사라져서 **DB가 걸러 주는 것이 없다.** 인가는 `proxy.ts`의
세션 검사가 전담한다. 새 라우트를 추가할 때:

- 미들웨어 matcher에서 빠지지 않는지 확인할 것
- 서버 액션과 API 라우트는 미들웨어를 우회할 수 있으므로 `isSignedIn()`으로 한 번
  더 검사할 것

크론 라우트(`/api/cron/*`)는 쿠키 없이 호출되므로 세션 검사에서 제외되어 있다.
`CRON_SECRET` 검증이 유일한 방어선이고, **여기가 뚫리면 DB 전체가 열린다.**

### 데이터 접근

`lib/db/sql.ts`의 태그드 템플릿으로만 붙는다. 보간값은 파라미터로 바인딩되므로
인젝션이 막힌다. **문자열을 이어붙여 쿼리를 만들지 말 것.**

`numeric` 컬럼(`documents.amount`)은 드라이버가 **문자열로** 돌려준다. 계산 전에
`Number()`를 통과시켜야 한다 — 안 하면 합계가 문자열 이어붙이기가 된다. 손익
정산과 증빙 목록에서 이미 처리되어 있으니 새 코드에서만 주의하면 된다.

### 스키마 변경

`db/schema.sql`은 초기 구축용이다. 이후 변경은 `db/migrations/0001_*.sql`부터
append-only로 쌓고, 기존 파일을 수정하지 말 것.

## 입력된 데이터

부서 10개: 기획운영팀 · 회계팀 · 마케팅부 · 콘텐츠팀 · 퍼포먼스팀 ·
영상콘텐츠팀 · 매장콘텐츠팀 · 개발팀 · 운영관리팀 · 부동산팀

표기는 **콘텐츠**로 통일했다. `name`이 unique 키라 '컨텐츠'로 적힌 값은 엑셀
일괄 등록에서 "알 수 없는 부서명"으로 실패한다.

사원 9명 (사번 0001~0009, 입사순). 재직 3명, 퇴사 6명.

기존 인사대장에서 옮기며 판단한 것:

- 사번이 원본에 없어 입사순으로 자동 채번했다. 실제 사번이 따로 있으면 사원
  상세에서 수정하면 된다.
- 부서 6명이 미지정이다. 문성혁은 대표라 소속이 없고, 나머지 5명은 소속 팀
  (디자인 / 브랜드마케팅 / "(주)옆커폰")이 없어진 퇴사자다.
- **아리의 생년월일이 원본에 `2097. 2. 8`로 적혀 있어 `1997-02-08`로 고쳤다.**
  오타로 판단한 것이므로 확인이 필요하다.
- 원본의 `직책`(팀장/인턴), `계약만료일`, `정규직전환일`, `연봉협상평가일`은
  담을 컬럼이 없어 옮기지 못했다.
